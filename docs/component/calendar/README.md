# Calendar 컴포넌트 설계

날짜 하나를 선택하고 월을 이동할 수 있는 공통 월간 캘린더의 설계 문서다. 날짜 계산·선택 UI와 일정 데이터·필터를 분리한다.

## 개요

| 출처            | 링크                                                                                                        | 확인한 내용                                                                                                   |
| --------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 컴포넌트 디자인 | [Figma — Calendar](https://www.figma.com/design/0UAYWaDS9UNjigV73HWcPZ/BizSched?node-id=775-55178)          | 월 제목·좌우 화살표, 필터 영역, 월요일부터 일요일까지 7열, 날짜별 셀, 큰 화면의 일정 칩과 작은 화면의 점 표시 |
| 사용 화면       | [Figma — Calendar 사용 UI](https://www.figma.com/design/0UAYWaDS9UNjigV73HWcPZ/BizSched?node-id=337-128539) | 화면 크기별 캘린더 배치와 필터가 열린 사용 예시                                                               |

두 노드의 스크린샷과 Calendar의 large(`775:55179`)·medium(`775:55245`)·small(`775:55310`) 하위 노드의 디자인 컨텍스트·치수를 확인했다. 이 디자인은 **일정을 담는 월간 보드**이며, Shadcn Calendar의 날짜 선택 기능 위에 셀 콘텐츠와 레이아웃을 조합한다. 실측값과 프로젝트 토큰에 맞춘 적용값은 아래 표에서 구분한다.

### 요청으로 확정된 범위

- 날짜는 단일 선택만 지원한다. 범위 선택·다중 선택은 지원하지 않는다.
- 헤더의 좌우 화살표 아이콘 버튼으로 월을 이동한다.
- 오늘은 날짜 숫자의 원형 배경, 선택일은 **셀 안쪽 테두리**, 키보드 포커스는 별도 표시로 구분한다.
- 선택일 셀 스타일은 Figma에 별도 정의가 없다. 확정한 안쪽 테두리 형태에 아래 기존 토큰 매핑을 적용한다.
- 공통 Dropdown 완성 후 결합한다.
- 일정 칩과 모바일 점 표시를 이번 설계·구현 범위에 포함한다(사용자 추가 확인).
- 선택한 날짜를 다시 눌러도 선택을 유지한다. 칩·점은 같은 상태 톤을 공유하고 신규 상태 표현은 아래 기존 토큰을 사용한다(사용자 추가 확인).
- 일정 칩·점은 날짜당 최대 3개를 표시한다. 초과분은 `+N`으로 표시하고, 누르면 해당 날짜를 선택한다(사용자 추가 확인).

### 일정 표시 범위

이번 설계는 월간 골격·날짜 선택·월 이동·오늘 표시와 **큰 화면의 일정 칩·작은 화면의 점 표시**를 포함한다. 공통 표현 컴포넌트도 함께 설계하되, 업무 완료 여부를 어떤 색상·아이콘으로 변환할지와 날짜별 일정 조회·정렬은 도메인이 맡는다. 칩·점은 최대 3개, 초과분은 `+N`, 클릭 시 해당 날짜 선택으로 확정했다. 날짜 아래 상세 목록은 별도 도메인 화면의 책임이다.

일정 생성·수정·드래그 이동, API 요청, 매장 필터 로직, 팝업 열고 닫기, 연·월 Dropdown 선택은 현재 요청에 포함되지 않았다. 필터 Dropdown과 연·월 선택기를 같은 기능으로 간주하지 않는다.

## 설계 결정 요약

사용자가 전체 추천안과 Shadcn 활용·톤 공유·치수 적용 방향에 동의했다. 아래 기준으로 구현하고 생성물의 실제 API와 시각 결과를 검수한다.

| 결정        | 선택                                          | 근거 / 상태                                                       |
| ----------- | --------------------------------------------- | ----------------------------------------------------------------- |
| 선택 모드   | 단일 날짜                                     | 사용자 요청 · 확정                                                |
| 월 이동     | 헤더의 이전·다음 버튼                         | 사용자 요청 · 확정                                                |
| 상태 표현   | 오늘은 숫자, 선택은 셀                        | 형태 확정. 아래 기존 토큰 매핑으로 적용                           |
| 공개 API    | 평면 props + 헤더의 `headerSlot`              | 사용자 확인 · 확정. 고정 골격에 필요한 조합 영역만 노출           |
| 상태 소유   | 선택일·표시 월은 호출부, 키보드 포커스는 내부 | 사용자 확인 · 확정. 일정 조회·URL·폼 연결 시 상태 복제 방지       |

| 파일 분리   | 컴포넌트 / 포커스 훅 / 날짜 계산 유틸리티     | 레이어 책임 규칙 준수. 불필요한 Context·Zustand는 도입하지 않는다 |

## 레이어 구조

Shadcn 생성물을 기반으로 아래와 같이 구성한다. 문서 작성 단계에서 파일이나 의존성을 생성하지 않는다.

```text
src/components/_common/ui/
└── calendar.tsx             # Shadcn Calendar, DayPicker 연결·기본 접근성

src/components/_common/Calendar/
├── Calendar.tsx             # 문자열 API 어댑터, Shadcn 조합·스타일
├── CalendarHeader.tsx       # 월 제목·화살표와 headerSlot 배치
├── CalendarDayCell.tsx      # Day 슬롯 확장, 날짜 버튼·일정·더보기 형제 배치
├── CalendarEventChip.tsx    # 일정 제목·아이콘·톤의 공통 표현
└── CalendarEventDots.tsx    # 작은 화면의 일정 점·요약 표현

src/lib/utilities/calendar/
└── calendarDate.ts          # 문자열 검증, DayPicker 날짜형과의 변환

src/lib/types/calendar.ts   # 날짜 변환 유틸리티의 공용 모델이 필요할 때만 추가

src/components/task/calendar/
└── ...                     # 일정 조회 결과·필터·상세 목록을 연결하는 도메인 조합
```

- Component의 `interface`는 해당 컴포넌트 내부에서 관리한다. 훅·유틸리티 타입은 각 레이어의 `types/`에 둔다.
- named export를 사용하고 배럴 `index.ts`는 만들지 않는다.
- 날짜 계산은 순수 유틸리티다. React 기능을 쓰지 않는 계산에 `use` 접두사를 붙이지 않는다.
- 월간 날짜 배열과 키보드 포커스는 DayPicker가 담당한다. 독자적인 `CalendarGrid`·`getCalendarDays`·`useCalendarFocus`를 함께 만들어 같은 동작을 이중 관리하지 않는다.
- 내부 파일 분리는 독립 책임·변경 가능성을 기준으로 한다. 요일 텍스트 같은 작은 마크업만을 위해 별도 컴포넌트를 만들지 않는다.
- 현재 실제 유틸리티 경로와 `components.json` alias는 `@lib/utilities/cn`을 사용한다. [folder-structure.md](../../architecture/folder-structure.md)의 `lib/utility/` 표기와 차이가 있어 기존 코드 경로인 `utilities`를 따른다.

### Shadcn Calendar 활용 — 확정

[Shadcn 공식 Calendar 문서](https://ui.shadcn.com/docs/components/base/calendar)에 따르면 Calendar는 React DayPicker 기반이며 단일 날짜 선택을 지원한다. [DayPicker의 커스텀 컴포넌트 가이드](https://daypicker.dev/guides/custom-components)는 날짜 셀 콘텐츠 추가와 기본 컴포넌트 조합을 지원한다. 이를 활용해 월간 일정 보드를 구성한다.

- 저장소의 `base-nova` 설정으로 Calendar를 생성하고 `_common/ui/calendar.tsx`를 기반으로 사용한다. 서비스 공개 컴포넌트는 `_common/Calendar/Calendar.tsx`에 둔다.
- 단일 선택, 월요일 시작, 인접 월 날짜 표시, 4~6주 가변 행을 설정한다. 재선택 해제와 중복 변경 콜백은 공개 컴포넌트에서 막는다.
- `month`·선택일·`today`는 공개 API에서 문자열로 유지한다. DayPicker가 요구하는 날짜 객체는 Client 내부 어댑터에서 `Asia/Seoul` 기준으로 변환하고, 콜백 결과는 날짜 문자열로 돌려준다. 날짜 객체를 Server → Client 경계에 전달하지 않는다.
- `Day` 셀을 확장해 기본 날짜 버튼 옆에 일정 칩·점·`+N`을 넣는다. `DayButton` 안에 클릭 가능한 일정 버튼을 넣지 않는다. 기본 ref·ARIA·tabIndex·키보드 이벤트를 보존한다.
- 월 제목·이전/다음 버튼은 기본 caption/navigation 기능을 조합해 배치하고 필터는 `headerSlot`으로 주입한다. 기본 연·월 Dropdown이나 Popover는 추가하지 않는다.
- 설치 전 `package.json`에는 `react-day-picker`·`date-fns`가 없었다. 구현 PR에서 Shadcn 생성물의 의존성을 설치하고 lockfile로 버전을 고정한다. 공식 DayPicker 문서의 최신 패키지명·API를 다른 버전 생성물에 그대로 복사하지 않고 설치 버전과 대조한다.
- 화살표는 Figma의 이중 chevron과 대응하는 설치된 lucide 아이콘을 사용한다. 생성된 import alias·기본 breakpoint·Button 의존성을 기존 코드와 대조한다. 기존 공통 컴포넌트를 무조건 덮어쓰지 않는다.

## API

```tsx
interface CalendarProps {
  selectedDate: string | null;
  onDateChange: (date: string) => void;
  month: string;
  onMonthChange: (month: string) => void;
  today: string;
  contentByDate?: Record<string, CalendarDayContent>;
  headerSlot?: ReactNode;
  label?: string;
  className?: string;
}

interface CalendarDayContent {
  full: ReactNode;
  compact: ReactNode;
  totalCount: number;
}
```

| prop            | 형식 / 기본값                             | 책임                                                           |
| --------------- | ----------------------------------------- | -------------------------------------------------------------- |
| `selectedDate`  | `YYYY-MM-DD` 또는 `null`, 필수            | 선택일. `null`은 아직 선택하지 않은 상태                       |
| `onDateChange`  | `(date: string) => void`, 필수            | 사용자가 선택한 날짜를 알린다                                  |
| `month`         | `YYYY-MM`, 필수                           | 현재 표시할 월. 선택일과 별개                                  |
| `onMonthChange` | `(month: string) => void`, 필수           | 이전·다음 월로 이동할 때 요청할 월을 알린다                    |
| `today`         | `YYYY-MM-DD`, 필수                        | 호출부가 같은 시간대 기준으로 계산한 오늘                      |
| `contentByDate` | 날짜 키 → `CalendarDayContent`, 생략 가능 | 큰 화면의 칩 목록과 작은 화면의 점 표현. 없는 날짜는 빈 콘텐츠 |
| `headerSlot`    | `ReactNode`, 생략 가능                    | 향후 필터 Dropdown 등을 조합할 영역                            |
| `label`         | 기본값 `캘린더`                           | 캘린더 영역의 접근 가능한 이름                                 |
| `className`     | 생략 가능                                 | 최상위 레이아웃 조정. `cn`으로 병합                            |

`string` 타입만으로 형식이나 실제 존재하는 날짜를 검증할 수 없다. 호출부에서 검증해 잘못된 값을 전달하지 않으며, 공통 날짜 계산 유틸리티도 월말·윤년을 포함해 검증한다. 잘못된 날짜를 임의로 오늘로 대체하지 않는다. 검증 실패를 사용자에게 알리는 방식은 입력을 소유한 도메인이 담당한다.

### 사용 예시

아래는 **Client Component 내부**에서 사용하는 예시다. 상태·콜백은 이 호출부가 소유하며, `initialMonth`·`initialSelectedDate`·`today`는 직렬화 가능한 문자열로 전달받는다.

```tsx
const [selectedDate, setSelectedDate] = useState<string | null>(
  initialSelectedDate,
);
const [month, setMonth] = useState(initialMonth);

<Calendar
  selectedDate={selectedDate}
  onDateChange={setSelectedDate}
  month={month}
  onMonthChange={setMonth}
  today={today}
  label="업무 일정 캘린더"
/>;
```

선택일과 표시 월을 내부 state에 다시 복제하지 않는다. URL 기반이면 호출부가 URL을, 폼이면 RHF를 단일 출처로 사용한다. 단순 화면에서는 위처럼 `useState`로 충분하다.

### Dropdown 결합

첫 구현에서 `headerSlot`이 없으면 월 제목과 화살표만 표시한다. 동작하지 않는 가짜 Dropdown을 만들지 않는다. 공통 Dropdown이 완성되면 호출부에서 조립한 요소를 `headerSlot`으로 전달한다.

필터 값·옵션·변경 콜백과 데이터 재조회는 도메인 소유다. Calendar는 Dropdown을 직접 import하거나 매장 목록을 가져오지 않는다. Dropdown API가 아직 없으므로 임의의 `Dropdown.Item` 같은 사용법을 문서에 확정하지 않는다.

날짜별 일정 콘텐츠는 `contentByDate`에 `full`·`compact` 두 표현으로 전달한다. 공통 Calendar는 같은 셀 안에서 CSS로 둘 중 하나만 노출하고, 업무 DTO·완료 상태 분기·정렬은 해석하지 않는다. 클릭 가능한 일정 콘텐츠는 날짜 선택 버튼의 **형제 요소**로 배치해 버튼 안에 버튼이나 링크가 중첩되지 않게 한다.

### 일정 칩·모바일 점

```tsx
interface CalendarEventChipProps {
  label: string;
  tone: 'muted' | 'accent';
  leadingSlot?: ReactNode;
  onClick?: () => void;
  className?: string;
}

interface CalendarEventDotItem {
  id: string;
  tone: 'muted' | 'accent';
}

interface CalendarEventDotsProps {
  items: CalendarEventDotItem[];
  label: string;
  className?: string;
}
```

| 영역           | 공통 컴포넌트 책임                                                 | 도메인 책임                                                   |
| -------------- | ------------------------------------------------------------------ | ------------------------------------------------------------- |
| 큰 화면의 칩   | 제목 한 줄 말줄임, 톤·선행 아이콘 배치, 클릭 가능 여부에 맞는 요소 | 제목·아이콘·톤 결정, 정렬, 상세 열기                          |
| 작은 화면의 점 | 전달된 항목별 점 표시, 안정적인 `id` key, 접근 가능한 요약         | 날짜별 항목과 표시 순서, 전체 일정 수·상태를 설명하는 `label` |
| 더보기         | `totalCount`로 초과분 계산, `+N` 버튼 표시, 날짜 선택 연결         | 전체 개수 전달, 선택된 날짜의 전체 일정 표시 위치·방식        |
| 반응형 콘텐츠  | 같은 날짜에 `full`·`compact`를 CSS로 전환                          | 두 표현을 같은 일정 데이터로 조립                             |

- 업무 일정은 **미완료 → `accent`(강조색), 완료 → `muted`(회색) + 체크 아이콘**으로 매핑한다. 점에도 같은 톤을 적용한다. 변환은 도메인이 맡고 공통 컴포넌트는 표시용 `tone`과 `leadingSlot`만 받는다. 색상 계열은 칩·점에서 공유하며 아래 토큰 매핑을 적용한다.
- 칩에 `onClick`이 있으면 `type="button"`, 없으면 비인터랙티브 요소를 사용한다. 표시 전용 칩에 가짜 클릭 동작을 붙이지 않는다. 상세 이동이 필요하면 링크 지원을 별도로 설계한다.
- 업무 일정 칩 클릭은 **해당 일정 상세를 여는 콜백만 실행**하며 선택 날짜를 바꾸지 않는다. 페이지 이동·모달 열기 등 실제 상세 표현은 호출부가 결정한다.
- 날짜 숫자와 셀의 빈 영역을 누르면 날짜를 선택한다. 날짜 선택 버튼이 이 영역을 담당하고, 일정 칩·`+N`은 형제 요소로 각자의 동작만 수행한다. 셀 컨테이너에 무조건적인 `onClick`을 달아 일정 클릭이 날짜 선택으로 전파되지 않게 한다.
- 점은 기본적으로 상태 요약이며 각각의 클릭 대상은 아니다. 장식 점을 `aria-hidden` 처리하고 요약 텍스트는 한 번 제공한다. 모바일 날짜 선택은 날짜 버튼으로 수행한다.
- `full`·`compact` 중 숨긴 표현은 `display: none`으로 포커스·접근성 트리에서도 제외한다. 같은 일정을 중복 낭독하거나 숨긴 칩에 Tab이 들어가면 안 된다.
- **노출·정렬 정책 확정:** 칩·점 모두 최대 3개다. 호출부가 전달한 순서를 유지하고 같은 앞 3개를 두 표현에 사용한다. Calendar 내부에서 완료 여부나 시간으로 재정렬하지 않는다.
- **초과분 정책 확정:** 전체 일정이 3개를 넘으면 `+{totalCount - 3}` 버튼을 표시하고, 누르면 해당 날짜를 선택한다. 3개 이하면 버튼을 표시하지 않는다. 예: 5개면 칩/점 3개와 `+2`.
- `CalendarDayContent.totalCount`는 해당 날짜의 전체 개수다. 호출부는 `full`·`compact`에 최대 3개만 조립하고, 공통 셀이 두 표현 아래 동일한 `+N` 버튼을 제공한다. `ReactNode` 내부를 분석해 일정 수를 세지 않는다.
- `+N` 버튼은 날짜 선택 버튼·일정 칩과 형제 요소로 두고 `type="button"`을 사용한다. 접근 가능한 이름은 날짜와 초과 개수를 포함한다. 별도 셀 확장·팝업 열기는 수행하지 않는다. 이미 선택된 날짜라면 선택을 유지하며, 추가 콜백 정책은 재선택 계약을 따른다.
- `contentByDate`는 표시 월에 필요한 날짜로 한정해 호출부에서 만든다. 표시 범위가 앞뒤 달을 포함한다면 해당 날짜 데이터 요청도 도메인에서 담당한다.

## 날짜·월 동작 계약 — 확정

| 상황                       | 확정 동작                                                                                           |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| 초기 상태                  | 호출부가 지정한 `month`를 표시한다. `selectedDate: null`이면 선택 셀이 없다                         |
| 날짜 선택                  | 해당 날짜 하나를 `onDateChange`로 전달하고, props가 갱신되면 선택 표시를 옮긴다                     |
| 같은 날짜 재선택           | 선택을 유지하고 `onDateChange`를 재호출하지 않는다. 이미 선택된 날짜의 `+N`도 동일                  |
| 앞뒤 달 날짜 선택          | 날짜 선택을 허용하고 해당 월로 이동한다. 변경된 값에 대해서만 `onDateChange`·`onMonthChange`를 호출 |
| 이전·다음 화살표           | `onMonthChange`만 호출한다. 선택일은 변경하지 않는다                                                |
| 연도 경계                  | 12월의 다음은 다음 해 1월, 1월의 이전은 전년도 12월                                                 |
| 선택일이 표시 월 밖에 있음 | 선택값은 유지하며, 현재 그리드에 날짜가 있을 때만 선택 표시한다                                     |
| 외부에서 선택일 변경       | 표시 월을 자동으로 바꾸지 않는다. 이동이 필요하면 호출부가 `month`도 함께 갱신한다                  |
| 오늘과 선택일이 같음       | 오늘 숫자 표시와 선택 셀 표시를 동시에 유지한다                                                     |
| 다른 월로 이동             | 오늘 날짜가 그리드에 있을 때만 오늘 표시한다                                                        |

### 월간 그리드

- 월요일 시작, 일요일 종료의 7열을 사용한다.
- 앞뒤 달 날짜도 표시하고 선택을 허용한다. 9월 화면에서 10월 1일을 누르면 선택일은 10월 1일, 표시 월은 10월로 변경한다. 인접 월의 `+N`도 같은 날짜 선택 계약을 따른다.
- 해당 달을 완전히 포함하는 **4~6주 가변 행**을 사용한다. 불필요한 주를 추가해 6주로 고정하지 않는다.
- 월 이동을 선택일의 일(day) 값에 의존시켜 계산하지 않는다. 1월 31일에서 다음 달로 이동할 때 3월로 넘쳐서는 안 된다.
- 윤년 2월, 30일·31일인 달, 주 시작·끝 경계를 테스트한다.

### 날짜와 시간대

날짜는 시각(timestamp)이 아닌 달력 날짜다. 서버 경계에서는 `Date` 객체를 전달하지 않고 날짜 전용 ISO 문자열을 유지한다. `new Date('YYYY-MM-DD')`나 `toISOString().slice(0, 10)`을 로컬 날짜 변환 규칙으로 쓰면 시간대에 따라 날짜가 달라질 수 있으므로 연·월·일 단위로 다룬다.

오늘은 **`Asia/Seoul` 기준**이다. 호출부가 계산한 `today`를 전달해 SSR과 첫 클라이언트 렌더를 일치시킨다. 호출부는 한국 자정과 화면 복귀 시 오늘을 다시 계산하고 갱신한다. 브라우저 시간대에 따라 오늘이 달라지지 않으며, 오늘 갱신만으로 선택일이나 표시 월을 변경하지 않는다.

## variant와 상태 스타일

현재 디자인만으로 불필요한 공개 `variant`·`size` 축을 만들지 않는다. 동일 골격의 반복 상태 차이는 `cva`, 외부 `className` 병합은 `cn`을 사용한다.

| 대상           | 상태 축                | 표현 책임                                                                      |
| -------------- | ---------------------- | ------------------------------------------------------------------------------ |
| 날짜 셀        | `isSelected`           | 셀 안쪽 테두리                                                                 |
| 날짜 숫자      | `isToday`              | 오늘 날짜 숫자의 원형 배경                                                     |
| 날짜 셀·숫자   | `isOutsideMonth`       | 인접 월임을 구분하는 표현. 낮은 대비로 읽을 수 없게 만들지 않는다              |
| 날짜 선택 버튼 | `focus-visible`        | 키보드 포커스. 오늘·선택 상태와 별개로 유지                                    |
| 일정 칩·점     | `tone: muted / accent` | 상태를 도메인에서 표시 톤으로 변환. 공통 cva 정의로 두 표현의 색상 일관성 유지 |

오늘과 선택일은 서로 배타적인 enum이 아니다. 독립 상태로 두고 필요하면 `compoundVariants`로 동시 상태를 처리한다. 오늘은 숫자의 원형 배경, 선택은 셀 안쪽 테두리, 키보드 포커스는 별도 표시로 구분한다. 선택 테두리가 셀 크기나 그리드 선을 밀어내지 않도록 구현한다. 색상값은 아래 기존 토큰 매핑을 적용한다.

## 디자인 토큰 매핑

사용자가 승인한 기존 토큰 활용 방향에 따라 다음 값을 적용한다. **같은 톤**은 칩과 점이 같은 상태·색상 계열을 공유한다는 뜻이며, 칩 배경·텍스트·점에 같은 HEX 하나를 강제한다는 뜻은 아니다. `tone="accent"`는 표시용 이름으로, CSS의 `bg-accent`에 자동 대응하지 않는다.

| 용도             | 적용                                                        | Figma 대조 / 근거                                                                                |
| ---------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 기본 표면        | `bg-white-50` (`#FFFFFE`)                                   | 날짜 셀 변수와 일치. 바깥 표면의 순백색도 기존 토큰으로 통일                                     |
| 인접 월 표면     | `bg-secondary-50` (`#FFFEFC`)                               | 셀 변수와 일치. 선택 불가 상태로 해석하지 않음                                                   |
| 월 제목          | `text-slate-500` (`#1C1917`)                                | Figma `#333333` 대신 프로젝트 본문 계열                                                          |
| 날짜·요일·더보기 | `text-slate-400` (`#6B6A68`)                                | 날짜 셀 변수와 일치. 요일의 `#737373` 및 더보기의 연한 회색도 읽기 가능한 같은 토큰으로 통일     |
| 셀 구분선        | `border-slate-200` (`#C6C5C5`)                              | 셀 변수와 일치. 일부 헤더의 `#DDDDDD`·`#E9EAEB`도 같은 선으로 통일                               |
| 미완료 칩        | `bg-primary-100 border-primary-400 text-accent-500`         | `#FFF9ED` / `#FFE6B3` / `#7A4E0B`, 셀 내부 칩 변수와 일치                                        |
| 미완료 점        | `bg-primary-500` (`#FFD98A`)                                | 강조 계열. 칩과 같은 `accent` 상태 매핑                                                          |
| 완료 칩          | `bg-slate-50 border-slate-200 text-slate-400` + 체크 아이콘 | Figma `#FAFAFA` / `#CCCCCC` / `#A4A4A4`를 프로젝트 회색 계열로 대응. 읽을 수 있는 글자 대비 유지 |
| 완료 점          | `bg-slate-400` (`#6B6A68`)                                  | 완료 칩의 전경색과 동일, `muted` 상태 매핑                                                       |
| 오늘 숫자        | `bg-primary-500 text-slate-500 rounded-full`                | 화면별 주황/노랑 강조를 하나의 오늘 상태로 통일. 원형 크기 24px                                  |
| 선택 셀          | 2px 안쪽 테두리, `primary-700` (`#CCAE6E`)                  | Figma 미정 상태에 적용한 기존 토큰. 셀 배경·크기를 바꾸지 않음                                   |
| 키보드 포커스    | 2px `slate-500` outline, 2px 간격                           | 선택 테두리와 다른 위치·색으로 식별. 컨테이너에서 잘리지 않게 검수                               |

Figma 스타일 설명의 `slate/400`은 `#A4A4A4`인 반면 일부 셀 변수 fallback과 코드의 `slate-400`은 `#6B6A68`이다. **이름만 보고 일치로 처리하지 않고** 위 표처럼 값과 용도를 함께 매핑한다. 인접 월 일정에 디자인의 `opacity: 0.6`을 일괄 적용해 글자 대비를 다시 낮추지 않는다.

새 전역 색상·radius 토큰은 만들지 않는다. 기존 radius 스케일에 없는 32px·24px는 컴포넌트 내 `rounded-[2rem]`·`rounded-[1.5rem]`으로 적용하고, 그림자는 Figma의 `0 0 60px rgb(0 0 0 / 0.05)`를 컴포넌트 스타일로 사용한다. 폰트는 저장소의 Pretendard를 사용한다. 적용 후 오늘·선택·포커스·완료 상태가 겹치는 경우까지 대비와 식별성을 검수한다.

## 치수와 반응형

### Figma 실측

아래는 컴포넌트 인스턴스 치수이며 viewport breakpoint를 의미하지 않는다. 높이는 헤더 필터가 있는 5주 예시 기준이다.

| 항목                  | large (`775:55179`)    | medium (`775:55245`)  | small (`775:55310`)   |
| --------------------- | ---------------------- | --------------------- | --------------------- |
| 전체                  | 1280 × 912px           | 636 × 662px           | 375 × 670px           |
| 헤더 높이             | 88px                   | 132px                 | 140px                 |
| 헤더 padding          | 가로 32px / 세로 20px  | 가로 16px / 세로 20px | 가로 16px / 세로 24px |
| 헤더 구성             | 월 이동·필터 가로 배치 | 세로 배치, gap 16px   | 세로 배치, gap 16px   |
| 바깥 radius           | 32px                   | 24px                  | 0                     |
| 요일 행               | 32px                   | 32px                  | 32px                  |
| 날짜 셀 높이          | 약 158.4px             | 약 99.6px             | 약 99.6px             |
| 셀 padding / 내부 gap | 8px / 4px              | 6px / 6px             | 6px / 6px             |
| 일정 표현             | 칩                     | 점                    | 점                    |

공통 치수: 날짜 원형·화살표 24px, 날짜·요일·칩 텍스트 12/16px, 월 제목 18/28px, 칩 padding 가로 8px·세로 4px 및 radius 6px, 점 8px·점 사이 간격 4px, 체크 아이콘 16px. 작은 화면에서 참조된 셀 원본은 88px 높이지만 **실제 배치된 인스턴스는 약 99.6px**이므로 후자를 기준으로 한다.

### 적용 기준

- 폭은 부모 안에서 `w-full min-w-0`, 날짜는 7등분한다. 컴포넌트 인스턴스의 1280·636·375px를 고정 폭이나 새 breakpoint로 사용하지 않는다.
- 셀 최소 높이는 실측을 정리해 큰 화면 **160px**, 작은 화면 **100px**로 적용한다. 전체 높이는 헤더 + 32px 요일 행 + 실제 4~6주 행 수로 결정한다. 912·662·670px 전체 높이를 고정해 6주 내용을 자르지 않는다.
- spacing은 `p-2` / `p-1.5`, `gap-1` / `gap-1.5`, `size-6` / `size-2`, `text-xs` / `text-lg` 등 기존 유틸리티를 사용한다. 칩 radius 6px는 현재 `rounded-sm`과 일치한다.
- 헤더 필터 슬롯이 없으면 불필요한 필터 줄과 간격을 제거한다. 헤더 높이를 강제하지 않고 padding과 실제 콘텐츠로 결정한다.

| 현재 프로젝트 viewport 구간              | 적용                                                         |
| ---------------------------------------- | ------------------------------------------------------------ |
| 1920px 이상, 기본 스타일                 | 일정 칩, 헤더 가로 배치, 셀 최소 160px, radius 32px          |
| 744px 이상 ~ 1920px 미만, `max-desktop:` | 일정 점, 헤더 세로 배치, 셀 최소 100px, radius 24px          |
| 744px 미만, `max-tablet:`                | 점·7열 유지, 셀 최소 100px, 헤더 세로 padding 24px, radius 0 |

이는 현재 `breakpoints.css`의 120rem·46.5rem을 그대로 사용하는 **Calendar 적용 기준**이다. 따라서 1440·1512px에서도 점 표현이 적용된다. [style.md](../../convention/style.md)의 공통 desktop 경계 재검토 자체를 이번 문서에서 확정하거나 전역 값을 변경하지 않는다. 공통 토큰이 바뀌면 Calendar도 같은 토큰을 따른다.

같은 원본의 앞 3개로 만든 `full`·`compact`를 CSS로 전환하고 `+N`은 동일하게 유지한다. 375px, 744px 전후, 1440px, 1920px 전후에서 제목·화살표·점·더보기의 겹침과 가로 넘침을 검수한다. 크기 판정용 JS 훅은 추가하지 않는다.

## 접근성

[accessibility.md](../../convention/accessibility.md)의 키보드 조작·포커스 보장 원칙을 따른다. Shadcn/DayPicker의 시맨틱·키보드 동작을 유지하고 슬롯 확장 후 다음 항목을 검수한다. 포커스 이동을 별도 엔진으로 재구현하지 않는다.

- 월 이동은 `<button type="button">`으로 구현하고 `이전 달`·`다음 달`의 접근 가능한 이름을 제공한다. 아이콘 자체는 `aria-hidden`으로 중복 낭독을 막는다.
- 월 제목은 `2026년 9월`처럼 읽을 수 있게 제공하고 월 변경을 `aria-live="polite"`로 알린다.
- DayPicker 그리드의 `grid` → `row` → `columnheader` / `gridcell` 구조를 유지한다. 역할만 붙이고 키보드 동작을 누락하지 않는다.
- 선택 셀에는 `aria-selected`, 오늘 날짜에는 `aria-current="date"`를 각각 사용한다. 날짜 버튼에는 연·월·일과 요일을 포함한 이름을 제공한다.
- 날짜 영역은 roving tabindex로 한 날짜만 Tab 진입점으로 둔다. 방향키는 좌우 1일·상하 1주, Home/End는 주의 시작·끝, PageUp/PageDown은 이전·다음 월, Enter/Space는 날짜 선택으로 연결하는 안을 제안한다.
- 포커스 이동만으로 선택일을 바꾸지 않는다. 키보드로 월 경계를 넘으면 표시 월 변경을 요청하고 렌더 후 대상 날짜로 포커스를 옮긴다. PageUp/PageDown의 목표 일자가 없으면 해당 월 말일로 보정한다.
- 첫 진입점은 표시된 선택일 → 표시된 오늘 → 표시 월 1일 순서를 제안한다. 헤더 버튼을 눌러 월을 바꿀 때는 버튼 포커스를 유지한다.
- 날짜 숫자와 선택 배경만으로 포커스를 대신하지 않는다. 오늘·선택·포커스가 같은 셀에 있어도 구별되어야 한다.
- 전경/배경 대비는 WCAG 2.1 AA 목표로 검수한다. Figma에 정의되지 않은 상태에 대비가 낮은 흰 글자·노란 배경 조합을 임의로 적용하지 않는다.

## 렌더링 경계

- `Calendar`의 상호작용 서브트리는 상태·포커스 훅과 DOM 이벤트 때문에 Client 경계가 필요하다([rendering.md](../../architecture/rendering.md), 트리거 1·3).
- 화면의 상태 소유 도메인 컴포넌트에 경계를 두고 `page.tsx`·`layout.tsx`는 Server Component로 유지한다. Server에서 일반 이벤트 콜백을 만들어 Calendar에 전달하지 않는다.
- 순수 날짜 유틸리티에는 `"use client"`를 붙이지 않는다. 클라이언트 경계에서 import되는 순수 마크업도 클라이언트 번들에 포함되므로 지시어가 없다는 이유만으로 독립 RSC로 설명하지 않는다.
- `headerSlot`에 서버 렌더 콘텐츠를 넣는 경우 Server 부모에서 `ReactNode`로 전달한다. 이벤트 콜백·렌더 함수를 경계 너머로 전달하지 않는다.
- 공통 Calendar는 Query·서버 캐시·Zustand store를 만들지 않는다. 일정 조회와 월별 캐시는 도메인에서 [state-management.md](../../architecture/state-management.md)·[data-flow.md](../../architecture/data-flow.md)를 따른다.
- 렌더마다 서버와 클라이언트에서 각각 현재 날짜를 읽지 않는다. 전달받은 `today`와 `month`로 첫 렌더를 일치시킨다.

## 테스트 전략

구현 시 [test.md](../../convention/test.md)에 따라 `test/`가 `src/` 구조를 미러링한다. 이번 문서 변경에서는 구현 테스트를 추가하지 않는다.

| 대상        | 검증                                                                                                           |
| ----------- | -------------------------------------------------------------------------------------------------------------- |
| 날짜 계산   | 윤년·평년 2월, 30일·31일, 주 경계, 12월↔1월, 4~6주 가변 행                                                     |
| 단일 선택   | 다른 날짜 선택 시 한 셀만 선택, 재선택 시 콜백 생략, 초기 미선택                                               |
| 월 이동     | 월 콜백만 실행, 선택값 유지, 선택일 31일에 영향받지 않는 월 계산                                               |
| 외부 제어   | 부모가 `month`·`selectedDate`를 변경하면 내부 복제 상태 없이 반영                                              |
| 상태 겹침   | 오늘만 / 선택만 / 오늘이면서 선택 / 포커스까지 겹친 셀                                                         |
| 인접 월     | 앞뒤 달 날짜·`+N` 선택 시 선택일과 표시 월 변경, 같은 날짜의 중복 선택 콜백 없음                               |
| 키보드      | Tab 진입점 하나, 방향키·주·월 이동, Enter/Space 선택, 월 전환 후 포커스                                        |
| 접근성      | 버튼 이름, 선택·오늘 의미, 월 제목 변경 안내, 중첩 인터랙티브 요소 없음                                        |
| 날짜 경계   | 같은 `today`로 SSR·첫 렌더 일치, 한국 자정·화면 복귀 시 오늘 갱신, 잘못된 날짜 검증·오늘 대체 없음             |
| 조합·반응형 | `headerSlot` 유무, 작은 화면 헤더 배치, 7열 유지, 선택 테두리로 크기 변화 없음                                 |
| 일정 콘텐츠 | 빈 날짜·일정 여러 개·긴 제목·혼합 톤, 칩과 점이 동일 데이터에 대응, 입력 순서 유지·완료/미완료 톤 매핑         |
| 일정 접근성 | 클릭 가능한 칩의 키보드 조작, 날짜 선택과 독립, 점 요약 한 번 낭독, 숨긴 표현의 포커스 제외                    |
| 노출·초과분 | 0·1·3개는 더보기 없음, 4개는 3개와 `+1`, 5개는 3개와 `+2`, 두 표현의 순서 일치, `+N`으로 날짜 선택·재선택 유지 |

## 단계별 PR 계획

[Modal의 PR 계획](../modal/README.md#단계별-pr-계획)과 같은 stacked pull requests 방식으로 진행한다. 각 브랜치는 바로 아래 브랜치를 base로 하고, 맨 아래만 `dev`를 향한다. 아래부터 Squash Merge하고 남은 PR의 base가 병합된 변경을 기준으로 연결되는지 확인한다.

| 순서 | 브랜치                        | base                          | 내용                                                                                              |
| ---- | ----------------------------- | ----------------------------- | ------------------------------------------------------------------------------------------------- |
| 1    | `feat/common-calendar`        | `dev`                         | **이 설계 문서** + `docs/README.md` · `docs/component/README.md` 인덱스 갱신                      |
| 2    | `feat/common-calendar-ui`     | `feat/common-calendar`        | Shadcn Calendar 도입 + 날짜 문자열 어댑터 + 단일 선택·월 이동·헤더 슬롯 + 오늘·선택·포커스 스타일 |
| 3    | `feat/common-calendar-events` | `feat/common-calendar-ui`     | 일정 칩·모바일 점 + 날짜별 콘텐츠·`+N` 조합 + 상태 톤·반응형 적용 및 시각 검수                    |
| 4    | `feat/common-calendar-test`   | `feat/common-calendar-events` | Vitest 테스트 — 날짜 변환·선택·월 이동·인접 월·초과분·콜백 분리·접근성 검증                       |

중간 브랜치를 수정하면 위쪽 브랜치에도 순서대로 rebase해 변경을 전파한다. 브랜치·리뷰·병합 절차는 [branch-strategy.md](../../collaboration/branch-strategy.md)·[pr-flow.md](../../collaboration/pr-flow.md)를 따른다.

> **후속 연동**: 공통 Dropdown 결합은 위 스택에 포함하지 않는다. PR 2에서 `headerSlot`을 준비하고, Dropdown 완성 후 최신 `dev`에서 `feat/common-calendar-dropdown`으로 분기해 별도 PR로 연결한다. Calendar 기본 기능의 병합을 Dropdown 완성까지 지연시키지 않는다.

## 구현 시 검수

사용자 확인이 필요한 기존 설계 항목은 위 방향으로 정리했다. 아래는 추가 승인 대기 사항이 아니라 구현 PR에서 수행할 검수다.

1. 생성한 Shadcn Calendar의 설치 버전·의존성·슬롯 API를 확인하고 날짜 객체 변환을 Client 내부로 한정한다.
2. Day 슬롯에 일정과 더보기를 추가한 후 날짜 버튼의 ref·ARIA·키보드 동작, 중첩 버튼 유무, 인접 월 선택·재선택 계약을 검증한다.
3. 칩·점이 같은 톤·순서를 공유하는지, 오늘·선택·포커스가 동시에 식별되는지 검수한다.
4. 위 실측과 적용값을 기준으로 4~6주 및 화면 크기별 배치를 확인한다. 프로젝트 공통 breakpoint는 이 작업에서 변경하지 않는다.

상세 화면의 위치·형태와 도메인별 일정 정렬 기준은 호출부의 책임이다. 공통 Dropdown은 해당 컴포넌트가 완성되면 확정한 `headerSlot`에 연결한다.

# 대시보드 페이지 설계

## 개요

로그인 후 처음 보는 화면이다. 사장님이 오늘 근무할 알바생과 이번 달 매출 추이를 한눈에 확인한다. 라우트는 `/dashboard`이며, 로그인·온보딩 완료 후 이 페이지로 이동한다([auth/README.md](../auth/README.md)).

## 화면 구성

| 섹션              | 컴포넌트             | 책임                                                                  |
| ----------------- | -------------------- | --------------------------------------------------------------------- |
| 헤더              | `DashboardHeader`    | `{name}님의 대시보드` 제목                                            |
| 오늘 근무 알바생  | `TodayWorkerSection` | 오늘 스케쥴을 오전·오후·저녁·야간 칸으로 나눠 표시                    |
| 이번 달 매출 차트 | `SalesChartSection`  | 이번 달 주차별 카테고리 누적 막대. `자세히 보기`는 `/sales/dashboard` |

## 상태·데이터

| 상태              | 범위        | 도구           | 근거                                                                              |
| ----------------- | ----------- | -------------- | --------------------------------------------------------------------------------- |
| 오늘 스케쥴       | 서버 데이터 | TanStack Query | `scheduleListQueryOptions({ from: today, to: today })` 재사용. **핵심 데이터**    |
| 이번 달 매출 차트 | 서버 데이터 | TanStack Query | `salesChartQueryOptions({ unit: 'MONTH', date })` 재사용. **핵심 데이터**         |
| 사용자 이름       | 서버 데이터 | TanStack Query | `meQueryOptions()` (`GET /api/users/me`). **서브 데이터** — `throwOnError: false` |

- 세 쿼리 모두 Server Component에서 prefetch하고 `HydrationBoundary`로 넘긴다. 첫 로드 때 브라우저의 `/api` 요청은 0건이어야 한다.
- 차트 params는 매출 대시보드와 같다. 두 페이지를 오갈 때 캐시를 공유한다.
- 카드는 각자 상태를 표시한다. `data`가 있으면 데이터, 없고 오류면 오류 문구, 둘 다 없으면 `불러오는 중`.
- 사용자 이름을 불러오지 못하면 제목은 `대시보드`로 표시하고, 다른 카드에는 영향을 주지 않는다.

## 렌더링 경계

- `page.tsx`는 Server Component다. prefetch만 하고, 데이터를 구독하는 세 섹션에만 `'use client'`를 붙인다.
- `getAuthHeaders()`가 쿠키를 읽으므로 페이지는 동적으로 렌더링된다. `connection()`은 쓰지 않는다.

## 설계 결정

| 결정                          | 내용                                                                                                                   | 근거                                                                                                                                                                                                                                                                     |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 시간대 구분 (2026-10-16)      | `startTime` 기준. 오전 `< 13:00`, 오후 `13:00 ~ 17:59`, 저녁 `18:00 ~ 21:59`, 야간 `≥ 22:00`. `09:00` 이전 시작도 오전 | 기획 기준이 없어 스케쥴 모달의 빠른 선택 칩 경계(09–13 / 13–18 / 18–22)와 맞춘다. 한 스케쥴은 한 칸에만 들어간다. 자정을 넘는 근무는 BE가 받지 않는다                                                                                                                    |
| 빈 시간대 (2026-10-16)        | 칸은 유지하고 `근무자 없음` 표시                                                                                       | 4열 그리드가 무너지지 않는다                                                                                                                                                                                                                                             |
| 삭제된 알바생 (2026-10-16)    | 표시하지 않는다                                                                                                        | 스케쥴 관리 화면과 같은 기준(`useScheduleList`의 `select`)                                                                                                                                                                                                               |
| 사용자 이름 출처 (2026-10-16) | `/me` 쿼리를 서버에서 prefetch                                                                                         | [auth.md](../../architecture/auth.md) "사용자 정보는 `/me` 조회로 얻는다". Zustand 메모리는 새로고침·자동 로그인 시 비어 있고, persist는 SSR hydration mismatch와 storage·쿠키 수명 불일치가 있으며, 쿠키 저장은 로그인·refresh·온보딩·프로필 수정마다 재설정이 필요하다 |

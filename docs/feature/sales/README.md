# 매출 기능 문서

## 개요

매출 현황을 요약하고 기간별 추이, 카테고리 구성, 입력 내역을 확인하고 매출을 관리하는 도메인이다. 전체 계획에는 조회·필터·입력·수정·삭제를 포함한다. 첫 UI PR에서는 `/sales/dashboard` 매출 대시보드의 데이터가 표시된 정적 화면을 구현한다.

## 주요 화면 / 플로우

| 화면          | 라우트             | 문서                           | 정적 UI PR                                          |
| ------------- | ------------------ | ------------------------------ | --------------------------------------------------- |
| 매출 대시보드 | `/sales/dashboard` | [dashboard.md](./dashboard.md) | 데이터가 표시된 대표 화면의 데스크톱·모바일 정적 UI |

빈 상태와 매출 입력·수정·삭제, 기간 필터, 내역 상세 이동은 전체 계획의 후속 단계다.

## API 명세

정적 UI PR은 API를 호출하지 않는다. 전체 계획에는 집계·기간별·카테고리별 매출과 내역 조회, 입력·수정·삭제 API가 필요하다. 엔드포인트와 응답 구조는 백엔드 명세가 제공되면 확정한다. [데이터 흐름 규칙](../../architecture/data-flow.md)에 따라 DTO를 FE DAO로 변환하고 오류를 처리한다.

## 상태 관리 포인트

정적 UI PR의 화면 값은 표시용 목업 데이터다. 이후 매출 조회·변경은 [상태 관리 규칙](../../architecture/state-management.md)에 따라 TanStack Query로 관리하고, 입력·수정 폼은 React Hook Form을 사용한다. 기간 필터의 URL 공유 여부는 후속 단계에서 결정한다.

## 주요 컴포넌트

- 기존 `AppSidebar`와 공통 `Card`를 화면 외곽과 카드 표면에 재사용한다.
- 입력 내역의 데스크톱 표는 `dev`의 shadcn/ui 기반 `Table`을 재사용한다. 공통 Table은 `dev`에 병합되어 있으므로 별도 선행 PR이 필요하지 않다.
- 매출 요약, 매출 차트, 카테고리 구성, 입력한 매출 목록은 매출 도메인 컴포넌트로 조합한다.
- 차트 구현은 [공통 Chart 설계](../../component/chart/README.md)를 따른다. 공통 Chart는 `dev`에 구현되어 있다.

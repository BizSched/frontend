## 화면 구성

추가와 수정은 같은 폼이라 컴포넌트 하나(`PartTimeStaffForm`)로 두고, 모드에 따라 제목·제출 버튼·초기값만 바꾼다. 컴포넌트는 `src/components/partTime/staff/`에 둔다.

| 모드 | 제목                       | 제출 버튼                  | 초기값                     |
| ---- | -------------------------- | -------------------------- | -------------------------- |
| 추가 | 아르바이트생 등록하기      | `등록하기` (모바일 `등록`) | 모두 빈 값                 |
| 수정 | 아르바이트생 정보 수정하기 | `수정하기` (모바일 `수정`) | 해당 아르바이트생의 상세값 |

- `PartTimeStaffForm` — 페이지 제목·제출 버튼과 폼 카드를 함께 `<form>`으로 감싸는 클라이언트 컨테이너. 제출 버튼이 카드 밖 제목 줄에 있어, 제목 줄까지 `<form>` 안에 두고 `type="submit"`으로 둔다. 카드 안은 공유 `PartTimeStaffProfileLayout`에 입력 요소를 채운다 ("상세와 공유하는 부품" 참고)
  - 카드 높이는 화면 아래까지 채우고, 본문(메모) 영역이 남는 높이를 차지한다. 글자 수 줄은 카드 아래 끝에 붙는다
  - 페이지 여백과 폼 가운데 정렬도 `PartTimeStaffForm`이 맡는다. 미리보기를 열면 폼 영역이 좁아져야 해서 `page.tsx`는 배경만 둔다
- `PartTimeStaffFormAttachments` — 첨부파일 박스. 공유 `PartTimeStaffAttachmentBox` 안에 업로드 트리거 행("첨부파일")을 맨 위에 두고, 그 아래에 추가한 순서대로 파일 행(파일 이름 + 삭제 ×)을 넣는다. 파일 행을 누르면 미리보기를 연다
  - 트리거 행 글자는 `#737373`으로 파일 이름(`#333`)보다 연하게 둔다. 입력 자리라 올린 파일과 구분되게 한다
- `PartTimeStaffAttachmentUploadModal` — "첨부파일 업로드" 모달. 공통 `Modal` + 파일 선택 영역 + `업로드` 버튼 ("첨부파일" 참고)
- 미리보기 — 상세의 `PartTimeStaffAttachmentViewer`를 그대로 쓴다. 상세 패널처럼 뷰어가 폼을 밀어 둘이 함께 보인다. dim은 두지 않는다. 뷰어 상단의 다운로드 버튼은 저장된 파일의 인증 조회 Blob 또는 새로 선택해 변환을 마친 로컬 파일의 Blob URL을 재사용하며, 해당 파일명을 지정한다 (2026-10-17)
  - 1024px 이상: 폼 영역과 뷰어를 한 줄에 놓는다. 뷰어는 화면 높이로 오른쪽에 붙고(sticky), 화면이 좁으면 상세 패널과 같이 폼 영역(기준 800px)과 뷰어(734px)가 함께 줄어든다. 뷰어를 접으면 폼이 다시 가운데로 온다
  - 1024px 미만: 뷰어는 화면 아래에 고정하고, 펼쳐져 있는 동안 폼 아래에 뷰어 높이만큼 여백을 둬 폼 끝까지 스크롤할 수 있게 한다

### 상세와 공유하는 부품

[staff.md "상세·폼 공유 구조"](./staff.md#상세폼-공유-구조)에서 정한 대로 레이아웃과 표시 부품만 공유하고 폼은 별도 컴포넌트로 둔다.

| 영역        | 공유 부품                                                      | 폼에서 넣는 것                                           |
| ----------- | -------------------------------------------------------------- | -------------------------------------------------------- |
| 헤더        | `PartTimeStaffNoteIcon`                                        | 이름 입력(24px/600, placeholder `#bbb`) + 글자 수 `N/30` |
| 인적 사항   | `PartTimeStaffProfileLayout` `fields`, `PartTimeStaffFieldRow` | 값 자리에 생년월일·성별·번호·시급 입력                   |
| 주간 스케쥴 | `extra`                                                        | 비운다                                                   |
| 첨부파일    | `PartTimeStaffAttachmentBox`, `PartTimeStaffAttachmentFile`    | 업로드 트리거 행 + 파일 행(이름 + ×)                     |
| 본문        | `body`                                                         | 메모 `textarea` + 하단 "공백포함 N자 \| 공백제외 N자"    |

- `PartTimeStaffFieldRow`의 라벨은 `<dt>`라 `<label>`로 입력과 묶이지 않는다. 입력에는 라벨과 같은 `aria-label`을 준다
- 744px 미만 배치(아이콘 32px, 인적 사항 1열 등)는 공유 부품이 이미 처리하므로 폼에서 다시 정하지 않는다

## 폼 필드

| 필드          | 라벨     | 필수 | 입력                | placeholder                      | 제약                                                                    |
| ------------- | -------- | ---- | ------------------- | -------------------------------- | ----------------------------------------------------------------------- |
| `name`        | —        | ○    | 텍스트              | 아르바이트생 이름을 입력해주세요 | 30자 이하 (`maxLength`). 앞뒤 공백 제거 후 1자 이상                     |
| `birthDate`   | 생년월일 | —    | 텍스트, 숫자 키패드 | 2XXX.XX.XX                       | 숫자 8자리를 `YYYY.MM.DD`로 표시. 실제 있는 날짜이고 오늘 이전이어야 함 |
| `gender`      | 성별     | —    | 공통 `RadioGroup`   | —                                | `female`·`male` 중 하나. 선택하지 않을 수 있다                          |
| `phone`       | 번호     | ○    | 텍스트, 숫자 키패드 | 010-XXXX-XXXX                    | 숫자만 받아 `010-XXXX-XXXX`로 하이픈 표시. `0`으로 시작하는 10~11자리   |
| `hourlyWage`  | 시급     | —    | 텍스트, 숫자 키패드 | -                                | 숫자만 받아 천 단위 콤마로 표시하고 뒤에 `원`을 붙인다                  |
| `attachments` | —        | —    | 업로드 모달         | —                                | "첨부파일" 참고                                                         |
| `memo`        | —        | —    | `textarea`          | 이 곳을 통해 메모를 작성해주세요 | 일반 텍스트, 줄바꿈 유지 ([staff.md](./staff.md#그-외))                 |

- **필수는 이름·번호 두 개** (2026-10-05 확정) — 카드 목록에 보이는 두 값이다. 나머지는 나중에 채울 수 있게 선택으로 둔다. 둘 다 채워지기 전에는 제출 버튼이 `disabled`다 (Figma 추가 화면의 회색 `등록하기`)
- **수정 모드는 바뀐 값이 없으면 제출 버튼이 `disabled`다** (2026-10-05 확정) — 바뀐 것 없이 수정 API를 호출하지 않는다. RHF `isDirty` 대신 제출 값으로 바꾼 결과를 초기값과 비교한다. 이름 앞뒤 공백처럼 제출 시 사라지는 차이는 바뀐 것으로 보지 않고, 값을 고쳤다가 초기값으로 되돌리면 다시 비활성화된다. 첨부파일은 목록의 `key`를 순서대로 비교해, 파일을 추가하거나 지우면 바뀐 것으로 본다. 필수 값 조건과 함께 본다 (Figma `수정하기`는 활성 상태만 있다)
- **생년월일은 텍스트 입력** (2026-10-05 확정) — 생년은 수십 년 전이라 공통 DatePicker로는 연도를 월 단위로 넘겨야 해 불편하다. `inputMode="numeric"`으로 받고, 입력 중 숫자 외 문자는 버리고 `.`을 자동으로 넣는다. 폼 값은 화면 표시 문자열(`YYYY.MM.DD`)로 두고, 제출 시 상세 타입과 같은 `YYYY-MM-DD`로 바꾼다. 라벨은 Figma "나이" 대신 "생년월일"이다 (2026-10-05 확정, [staff.md](./staff.md#figma와-다르게-해석하는-부분)). 상세와 폼이 같은 `PartTimeStaffFieldRow`를 쓰므로 라벨 폭(56px)도 함께 바뀐다
- **성별은 공통 `RadioGroup`** (2026-10-05 확정) — 두 항목 중 하나를 고르는 입력이라 한 번에 고를 수 있는 라디오가 맞는다. `여성`·`남성`을 값 자리에 한 줄로 놓는다. 공통 `RadioGroup`은 해제를 지원하지 않으므로, 한 번 고르면 미선택으로 되돌릴 수 없다
- **번호·시급도 표시 문자열과 제출 값을 나눈다** — 번호는 하이픈 포함 문자열 그대로(상세 타입 `phone`과 같은 형식), 시급은 콤마를 뺀 `number`로 바꿔 제출한다
- **인적 사항 입력은 테두리 없는 텍스트 자리** — Figma는 값 자리에 상세와 같은 14px 텍스트만 있다. 공통 `Input`은 테두리·높이 56px 고정이라 이 자리에 맞지 않아, 네이티브 `<input>`을 상세 값과 같은 글자 스타일로 둔다. 이름 입력·메모 `textarea`도 같은 이유로 네이티브 요소를 쓴다
- **포맷 입력은 커서 위치를 지킨다** — 구분자를 다시 넣으면 브라우저가 커서를 끝으로 옮기므로, 커서 앞 숫자 개수를 기준으로 포맷 뒤 커서를 되돌린다. 구분자 바로 뒤에서 백스페이스를 누르면 구분자가 다시 붙어 키가 먹지 않는 것처럼 보이므로, 그 앞 숫자를 지운다
- **포맷 함수는 유틸로 분리하고 테스트한다** — 생년월일·번호·시급의 입력 정리(숫자만 남기기 + 구분자 넣기)와 커서 위치, 제출 값 변환, 변경 여부, 메모 글자 수 계산은 `src/lib/utilities/partTime/partTimeStaffForm.ts`에 두고 단위 테스트를 작성한다

### 글자 수

- 이름 `N/30` — `N/`은 `#737373`, `30`은 `#ebc87f`(Figma 값, `primary-600`). 30자에 닿으면 더 입력되지 않는다
- 메모 "공백포함 N자 | 공백제외 N자" — 공백제외는 줄바꿈을 포함한 모든 공백 문자를 뺀 수다
- 글자 수는 문자열 `length`(UTF-16 단위)로 센다. 이모지 등은 2자로 센다 (2026-10-14 확정). BE 상한을 넘지 않도록 BE와 같은 단위로 세고, 화면 표시와 제한도 같은 값을 쓴다. 상한에서 자를 때 이모지의 절반만 남지 않도록 서로게이트 쌍을 나누지 않는다
- 이름 30자 자르기는 한글 조합 중에는 하지 않고 조합이 끝난 뒤(`compositionend`) 한다. 조합 중에 값을 바꾸면 브라우저에 따라 글자가 중복되거나 조합이 깨진다

## 첨부파일

| 단계        | 동작                                                                                                                          |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 업로드 열기 | 첨부파일 박스의 "첨부파일" 행을 누르면 "첨부파일 업로드" 모달을 연다                                                          |
| 파일 고르기 | 파일 선택 영역("파일을 선택해주세요")으로 파일 하나를 고른다. 고르면 파일 이름 + ×로 바뀌고 × 로 선택을 취소한다              |
| 업로드      | `업로드` 버튼을 누르면 폼의 `attachments`에 추가하고 모달을 닫는다. 파일을 고르기 전에는 `disabled`                           |
| 미리보기    | 박스의 파일 행을 누르면 뷰어를 연다. 새로 고른 파일은 `URL.createObjectURL`로 그리고, 행을 지우거나 페이지를 떠날 때 해제한다 |
| 삭제        | 파일 행의 ×를 누르면 폼 값에서 뺀다. 수정 모드의 기존 파일도 제출 전까지는 폼 값에서만 빠진다                                 |

- **파일 선택 영역은 모달 안의 임시 마크업** (2026-10-05 확정) — 이 자리는 공통 Input 설계의 `UploadInput`(`feat/common-file-input`)이 맡는다. 공통 `UploadInput`이 아직 `dev`에 없고, MVP에는 고른 파일(이름 + ×) 표시가 없다. 모달 안에 숨긴 `<input type="file">` + 점선 트리거와 고른 뒤 상태만 Figma대로 두고, 공통 `UploadInput`이 들어오면 이 영역만 바꾼다. 공통 폴더에는 만들지 않는다
- **받지 않는 형식은 고르지 않은 것으로 둔다** — 파일 창에서 "모든 파일"로 바꿔 `accept`에 없는 형식의 파일을 고르면 선택하지 않은 것으로 두고, 이전 선택을 유지한다. 폼과 같이 메시지는 두지 않는다
- **모달은 공통 `Modal` + overlay-kit으로 연다** — 스케쥴 추가·수정 모달과 같은 경로(`openPartTimeStaffAttachmentUploadModal`)로 열어 모달 쌓임 순서를 맞춘다 ([schedule.md "열기·닫기"](./schedule.md#열기닫기)). 고른 파일은 Promise 결과로 폼에 돌려준다
  - Figma: 데스크톱·태블릿 456px 중앙(radius 40px, padding 32px), 모바일 343px 중앙. 모바일도 바텀시트가 아니라 중앙 모달이다
- **서버 전송은 제출 시점** — 업로드 모달은 파일을 폼 값에 담기만 한다. 제출할 때 BFF 요청 body 한도(4MB) 안에 들도록 파일을 한 요청에 하나씩 보낸다 (2026-10-14 확정, [도메인 문서 설계 결정](./README.md#설계-결정))
  - 등록: 정보만 JSON으로 `POST`한 뒤, 새 아르바이트생에 파일을 하나씩 수정 API(`PATCH`, `multipart`)로 올린다. 파일 업로드가 실패하면 이미 등록된 아르바이트생의 수정 페이지(`/partTime/staff/{id}/edit?uploadFailed=1`)로 이동하고 인라인으로 알린다. 저장된 첨부 목록을 확인하고 빠진 파일만 다시 고른다. 등록 폼에서 다시 제출하면 같은 아르바이트생이 두 번 등록되기 때문이다 (인라인 안내 2026-10-16 확정)
  - 수정: BE 수정 API는 파일을 추가만 한다. 폼에서 뺀 기존 파일(`kind: 'saved'`)은 파일마다 첨부파일 삭제 API를 호출한다. 순서는 삭제 → 정보 수정(JSON) → 파일 추가(하나씩)다 (2026-10-14 확정). BE는 기존 개수와 새 개수의 합이 10을 넘으면 파일 추가를 거부하므로, 파일을 바꿔 넣을 때 삭제가 먼저 끝나야 한다
    - 한 요청이라도 실패하면 뒤 요청은 보내지 않는다. 폼은 그대로 두고 토스트로 알린다 (2026-10-20 확정)
    - 다시 제출하면 끝나지 않은 요청만 보낸다. 이미 지워진 파일의 삭제가 404면 지워진 것으로 보고, 이미 올린 파일은 다시 올리지 않는다
    - 일반 정보 `PATCH`의 네트워크·5xx·응답 검증 오류 뒤에는 다음 제출에서 상세를 다시 조회해 저장 기준값을 갱신한다. 재조회가 실패하면 변경 요청을 보내지 않고 입력을 유지하며, 다음 제출에서 다시 조회한다
    - 업로드 응답에서 새 첨부 ID가 정확히 하나일 때만 이번 파일로 기록한다. 새 ID가 여러 개면 파일명이 같아도 추측하지 않고 재제출을 차단해 저장된 목록 확인을 안내한다
    - 모두 성공하면 목록·상세 쿼리를 무효화하고 상세로 이동한다
    - 부분 성공 때도 반영된 목록·상세 캐시를 갱신한다. 정보 수정에서 이름을 바꾸면 스케쥴 조회도 갱신한다
  - 직원 등록 `POST`·파일 추가 `PATCH`의 네트워크·5xx·응답 검증 오류는 서버 저장 여부가 불명확하므로 재제출을 차단하고 목록 또는 해당 상세 확인 링크를 표시한다 (2026-10-16 확정). 등록 후 파일 실패는 위 수정 페이지 이동으로 저장된 목록을 확인한다. 4xx로 저장 거절이 확인된 실패와 일반 정보 `PATCH`·파일 `DELETE`는 다시 제출할 수 있다. 이 제한은 현재 폼 세션에 적용하며, BE의 요청 중복 방지 키 도입은 별도 과제다
- **이미지는 고를 때 크기를 줄인다** (WebP 전환 2026-10-17) — 긴 변 2000px 이하, WebP 품질 0.8로 다시 인코딩한다. 실제 결과 MIME이 `image/webp`가 아니거나 결과가 없으면 JPEG 품질 0.8로 다시 처리한다. WebP는 투명 영역을 유지하고 JPEG 대체 시에는 흰 배경을 넣는다. 파일의 MIME·확장자는 실제 인코딩 결과로 정하고, 변환한 파일을 폼 값과 미리보기에 쓴다. HEIC도 브라우저가 열 수 있으면 같은 경로로 변환한다
- **3.5MB를 넘는 PDF는 받지 않는다** (2026-10-14 확정) — 브라우저에서 PDF를 줄일 수 없어서다. 고르지 않은 것으로 두고 "3.5MB 이하 파일만 올릴 수 있어요."를 토스트로 알린다 (2026-10-20 확정). WebP 또는 JPEG 변환 후에도 3.5MB를 넘는 이미지에 같은 한도를 적용해 multipart 요청 여유를 확보한다. 이미지 처리 실패도 토스트로 알리고 이전 선택을 유지한다
- **받는 형식은 jpg·jpeg·png·webp·pdf, 개수는 10개까지** (WebP 추가 2026-10-17) — `accept`를 `.jpg,.jpeg,.png,.webp,.pdf`로 둔다. BE는 doc·docx도 받지만 브라우저가 그리지 못해 미리보기를 할 수 없다. 기존 파일과 새 파일이 합쳐 10개면 "첨부파일" 행을 비활성화한다. 파일 형식은 업로드할 때 MIME으로 정해 `type`에 담는다

### API 연동 계획

1. 수정 페이지는 이미 `fetchQuery` → `HydrationBoundary` → `PartTimeStaffEditForm`으로 상세를 연결한다. `notFound()`가 필요해 `prefetchQuery` 대신 `fetchQuery`를 쓴다. 재조회 실패에도 미저장 입력을 유지한다
2. `useSaveStaff`의 한 mutation이 삭제·정보 저장·파일별 추가를 순서대로 실행한다. 완료한 삭제·정보 수정·신규 파일의 서버 ID를 기록해 재제출 시 건너뛴다. 부분 업로드에 성공한 새 파일을 폼에서 제거하면 다음 제출 때 서버에서도 삭제한다
3. 생성된 등록·수정 함수가 multipart만 만들고 파일 파트를 포함하지 않아, `entities/staff/api.ts`에서 생성 URL·DTO·응답 zod 스키마를 재사용하고 `customFetcher`로 JSON·FormData를 전송한다. 생성 파일은 직접 수정하지 않는다
4. BE `message`는 `ts-pattern`을 사용하는 `formatCommonError`로 표시한다. mutation의 자동 재시도·경계 위임은 사용하지 않는다
5. 제출 중 입력·파일 변경·중복 제출을 막고, 성공 시 `router.replace`로 상세를 연다
6. 전화번호 필수·기존 입력 검증은 유지한다. 기존 생년월일·성별·시급을 비우는 동작은 BE 계약 확인 전까지 제출을 막고 이유를 인라인으로 표시한다 (2026-10-16 확정). 신규 등록의 빈 선택값과 메모의 빈 문자열 삭제는 기존 계약을 따른다

## 렌더링 경계

- `app/(main)/partTime/staff/new/page.tsx`, `app/(main)/partTime/staff/[id]/edit/page.tsx`는 Server Component다. 수정 페이지는 `params.id`로 상세를 조회해 hydration한다. 파일 처리와 저장 진행 기록은 클라이언트에서만 관리한다

### 그 외

- **모바일 제출 버튼은 상단 바 오른쪽** (2026-10-05 확정) — Figma처럼 모바일 상단 바에 `등록`·`수정` 텍스트 버튼을 둔다. 상단 바는 공통 사이드바 영역이라 페이지 액션을 넣을 슬롯이 필요하다. 슬롯이 생기기 전까지는 페이지 제목 줄 오른쪽에 둔다. 상단 바로 옮기면 버튼이 `<form>` 밖에 렌더되므로 `form` 속성으로 폼 `id`와 연결한다
- **페이지 이탈 시 확인 모달을 띄운다** (2026-10-05 확정) — 입력 중(`isDirty`) 뒤로가기·사이드바 이동 시 "작성 중인 내용이 사라집니다." 확인을 공통 `Modal`로 띄운다. 제출 성공 후 이동은 확인하지 않는다. App Router에는 이동 가로채기 API가 없어 뒤로가기(`popstate`)와 링크 클릭을 따로 처리한다. 새로고침·탭 닫기는 `beforeunload`라 브라우저 기본 확인창만 띄울 수 있다
- **취소 버튼은 두지 않는다** — Figma에 없다. 브라우저 뒤로가기·사이드바로 나간다
- **제출 후 이동** (2026-10-05 확정) — 추가는 목록 1페이지에서 등록한 아르바이트생 상세를 연다(`/partTime/staff?staffId={새 id}`). 수정은 해당 아르바이트생 상세(`/partTime/staff?staffId={id}`)로 간다. 둘 다 `router.replace`한다. 폼 페이지가 히스토리에 남으면 뒤로가기로 제출한 폼에 다시 돌아온다. API 연동 전에는 새 `id`가 없어 추가는 목록 1페이지로만 이동한다
- **없는 `id`로 수정 페이지에 들어오면 `notFound()`** — 목록의 `?staffId=`와 달리 이 페이지는 수정 대상 없이는 그릴 것이 없다. 숫자가 아닌 `id`도 같다
- **메모는 500자에서 입력을 막는다** (2026-10-14 확정) — BE 최대 500자에 맞추고, 이름 30자와 같은 방식(UTF-16 단위, 한글 조합이 끝난 뒤 자르기)으로 막는다. Figma에 상한 표시가 없어 글자 수 줄은 그대로 둔다
- **검증 메시지는 두지 않는다** — Figma에 에러 표시가 없어, 값이 유효하지 않으면 제출 버튼만 비활성화한다. 생년월일을 `2001.13.40`처럼 잘못 넣으면 이유가 보이지 않으므로, 이후 개선 사항으로 필드별 에러 표시를 다시 검토한다

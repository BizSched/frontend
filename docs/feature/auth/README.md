# 인증 기능 문서

## 개요

로그인, 회원가입, 소셜 로그인 후 추가 정보 입력을 다룬다. 서비스 이용에 필요한 **업종**과 **약관 동의**는 가입 경로와 무관하게 모든 회원에게서 받는다.

## 주요 화면 / 플로우

| 경로          | 화면                | 문서                             |
| ------------- | ------------------- | -------------------------------- |
| `/login`      | 로그인              | —                                |
| `/signup`     | 일반 회원가입       | [signup.md](./signup.md)         |
| `/onboarding` | 소셜 가입 추가 정보 | [onboarding.md](./onboarding.md) |

```
로그인:     /login → /dashboard
일반 가입:  /signup (계정 정보 + 업종 + 약관) → /dashboard
소셜 가입:  소셜 로그인 → /onboarding (업종 + 약관) → /dashboard
```

일반 가입은 회원가입 화면에서 업종과 약관을 함께 받는다. 소셜 가입은 회원가입 화면을 거치지 않으므로 같은 항목을 `/onboarding`에서 받는다.

인증 API가 정해지기 전까지 로그인·회원가입·온보딩 제출은 입력값 검증 없이 `/dashboard`로 이동만 한다.

## API 명세

엔드포인트와 요청·응답 구조는 미정이다. 확정된 값은 업종 enum뿐이다.

| 값                  | 표시     |
| ------------------- | -------- |
| `RESTAURANT`        | 음식점   |
| `CAFE`              | 카페     |
| `BAKERY`            | 베이커리 |
| `PUB`               | 주점     |
| `CONVENIENCE_STORE` | 편의점   |
| `CUSTOM`            | 직접입력 |

`CUSTOM`을 고르면 직접 입력한 업종명을 `businessTypeCustom` 필드로 받는다. 서버 필드명은 API 명세에 맞춰 조정한다.

## 상태 관리 포인트

| 상태                          | 도구            | 근거                                                      |
| ----------------------------- | --------------- | --------------------------------------------------------- |
| 로그인·회원가입·온보딩 입력값 | React Hook Form | 폼 상태 규칙. 제출 시 필수 약관·업종 검증을 한곳에서 처리 |
| 약관 체크 상태                | React Hook Form | `terms` 필드 하나에 객체로 둔다                           |
| 약관 전문 모달 열림 상태      | overlay-kit     | 모달 결과(동의 여부)를 `await`로 받아 체크에 반영         |

`TermsAgreement`와 `AuthBusinessTypeField`는 값을 갖지 않는 controlled 컴포넌트다. 두 화면이 같은 컴포넌트를 쓰고, 각 폼이 `Controller`로 값을 연결한다.

## 주요 컴포넌트

| 컴포넌트                | 책임                                                                    |
| ----------------------- | ----------------------------------------------------------------------- |
| `LoginForm`             | 로그인 폼 상태, 제출 후 대시보드 이동                                   |
| `SignupForm`            | 회원가입 폼 상태, 제출 후 대시보드 이동                                 |
| `OnboardingForm`        | 온보딩 폼 상태, 제출 후 대시보드 이동                                   |
| `AuthBusinessTypeField` | 업종 드롭다운, `CUSTOM` 선택 시 직접 입력 칸 노출                       |
| `TermsAgreement`        | 전체 동의·필수 4종·선택 마케팅 체크, 전문 보기                          |
| `TermsModal`            | 약관 전문 표시. `동의하기`를 누르면 해당 항목을 체크한다                |
| `terms.ts`              | 서비스 이용약관, 개인정보 처리방침, 근로자 개인정보 처리 위탁 특약 본문 |

### 약관 체크 규칙

| 동작                    | 결과                                             |
| ----------------------- | ------------------------------------------------ |
| 전체 동의               | 필수 4종과 마케팅 수신 수단 2종을 모두 켜고 끈다 |
| 마케팅 수신 체크        | 이메일·SMS를 함께 켜고 끈다                      |
| 이메일·SMS 중 하나 체크 | 마케팅 수신이 체크된 것으로 표시된다             |
| 전문 보기 → 동의하기    | 해당 필수 항목을 체크한다. 닫기·ESC는 변화 없음  |

약관 전문은 Form 계열 모달([Modal 설계](../../component/modal/README.md))을 쓴다. 본문이 길어 페이지에 펼치면 가입 폼이 밀려나기 때문이다.

## 확인 필요

### 1. 개인정보 수집 항목과 실제 입력 항목 불일치

동의 문구와 개인정보 처리방침 제1조의 수집 항목이 실제 입력과 다르다.

| 구분                  | 항목                                                          |
| --------------------- | ------------------------------------------------------------- |
| 문구에만 있음         | 휴대전화번호, 사업장명, 사업자등록번호, 대표자명, 사업장 주소 |
| 입력에만 있음         | 이름, 업종                                                    |
| 소셜 가입에 해당 없음 | 비밀번호                                                      |

수집 항목을 실제 입력에 맞출지, 입력 항목을 늘릴지 결정이 필요하다.

### 2. 약관 미기재 값

`{{시행일}}`, `{{고객센터 이메일}}`, `{{고객센터 전화}}`, `{{클라우드 사업자}}`, `{{PG사명}}`, `{{알림 발송 사업자}}`, `{{CPO명}}` 등이 그대로 노출된다. 개인정보 처리방침 제5조(국외 이전)는 해외 리전을 쓰지 않으면 삭제한다.

### 3. 필수 항목 검증

필수 약관 4종과 업종 선택이 빠졌을 때 제출을 막는 규칙과 오류 표시 방식이 정해지지 않았다.

### 4. `/onboarding` 진입 조건

소셜 로그인 후 신규 회원을 판별해 `/onboarding`으로 보내는 기준과, 로그인하지 않은 사용자의 직접 접근 처리가 정해지지 않았다.

### 5. `components/auth/` 하위 폴더

[folder-structure.md](../../architecture/folder-structure.md)는 `auth/form/` 하위 폴더를 두지만 현재 auth 컴포넌트는 모두 `auth/` 바로 아래에 있다.

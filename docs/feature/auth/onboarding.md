# 온보딩 페이지 설계

## 개요

소셜 로그인으로 처음 가입한 사용자에게 업종과 약관 동의를 받는다. 소셜 가입은 회원가입 화면을 거치지 않으므로, 일반 가입과 같은 항목을 이 화면에서 받는다. 라우트는 `/onboarding`이며, 완료 후 `/dashboard`로 이동한다.

## 화면 구성

| 영역      | 구성                             |
| --------- | -------------------------------- |
| 헤더      | 제목 `추가 정보 입력`, 안내 문구 |
| 업종      | `AuthBusinessTypeField`          |
| 약관 동의 | `TermsAgreement`                 |
| 액션      | 시작하기                         |

레이아웃은 `AuthLayout`을 써서 회원가입 화면과 같은 폭·로고를 유지한다. 회원가입과 달리 제목을 화면에 보여준다. 로그인 직후 바뀐 화면이 무엇인지 알려야 하기 때문이다.

## 상태·데이터

| 상태        | 범위             | 도구            |
| ----------- | ---------------- | --------------- |
| 입력값 전체 | `OnboardingForm` | React Hook Form |

저장 API가 정해지지 않아 제출 시 `/dashboard` 이동만 한다.

## 렌더링 경계

`page.tsx`는 Server Component로 레이아웃·제목·메타데이터를 담당한다. 폼 상태와 라우터 이동이 필요한 `OnboardingForm`부터 Client Component다.

## 설계 결정

| 결정          | 선택                            | 근거                                                                      |
| ------------- | ------------------------------- | ------------------------------------------------------------------------- |
| 라우트 위치   | `app/onboarding/` (`(main)` 밖) | 로그인 후 화면이지만 가입이 끝나지 않은 단계라 사이드바를 보여주지 않는다 |
| 입력 컴포넌트 | 회원가입과 공유                 | 두 경로에서 받는 항목과 규칙이 같다                                       |
